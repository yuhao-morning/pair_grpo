# LLM 裁判校准：比较 vs 逐条打分，事先约定（写于任何裁判调用之前，2026-10-27）

## 问题

在同一个裁判、同一份任务说明、同一批轨迹摘要上，哪种方式给出的两两好坏判断更接近真实结果？三种方式：
- 逐条打分；
- 直接两两比较；
- 组内排名（listwise）。

不做训练，只测判断质量。这直接对应动机："比较比打分更容易、更准"。

## 数据（`calib_data.py`，已生成，没有调用 API）

- 环境：LunarLander-v3。一个 PPO 策略（种子 200），在 0 / 100k / 250k / 500k / 1M 步时的 5 个检查点，覆盖从总坠毁到稳定着陆。
- 每个阶段 16 组，每组 K=8 条轨迹，同一个 reset seed。
- 在 t = 0, 50, 100, … 处抽检查点，每个阶段最多抽 60 个，共 279 个检查点、2,046 条后缀、6,792 个配对。
- **摘要内容：** 剩余步数、结局（着陆停稳 / 坠毁或出界 / 超时仍在飞）、主引擎和侧引擎点火步数，以及每 25 步一帧的 x、高度、速度、倾角、触地的腿（最多 12 帧）。**不含任何奖励项。**
- **金标准：** 从 t 起的折扣回报 G_t（γ = 0.99），与训练时的 oracle 一致。金标准相等的配对排除。

## 裁判

- 模型：`gemini-3.5-flash-lite`，`thinkingLevel: minimal`，JSON 结构化输出。
- 三种方式用同一段任务说明。说明里只给目标（在两旗之间的着陆台上平稳直立降落、少用燃料、不坠毁不出界），不给任何权重。
- **逐条打分：** 每条后缀单独打 0–10 分，同分算平局。另随机抽 300 条重复打一次，测重复一致性。
- **直接两两：** 每个检查点随机抽 3 对，按 A/B 和 B/A 两种顺序各问一次；回答 A、B 或 SAME。
- **组内排名：** 每个检查点一次排出全部后缀，允许并列分层。按随机顺序和反转后的顺序各问一次，由此推出全部配对。
- **花费：** 按付费标准价（输入 $0.30、输出 $2.50 / 百万 token）累计，到 $10 自动停止。所有请求和响应都缓存在本地，重跑不会重复花钱。

## 指标

- **主指标：有效准确率**——在金标准有胜负的配对上，判对记 1、判错记 0、判平局记 0.5。
  - 对两种有两个顺序的方式，两个顺序都计入，即各占一半权重。
  - 按 z = |ΔG| / σ_t 分 4 段报告：< 0.5、0.5–1、1–2、> 2。σ_t 是该检查点所有后缀 G 的标准差。
- **辅助指标：**
  - 平局率；
  - 位置一致性（两种顺序给出相同判断的比例）；
  - 打分的重复一致率；
  - 每个检查点内裁判排序与 G 的 Spearman 相关。

为了公平，三种方式在**同一组配对**上比较：每个检查点那 3 对，三种方式都有判断。另外，逐条打分和组内排名都覆盖全部 6,792 对，也单独报告这一更大集合上的结果。

## 检验

在检查点层面做 bootstrap（2,000 次，按检查点整群重采样），算有效准确率差值的 95% 区间。

- **H1：** 组内排名 − 逐条打分，在全部配对上。
- **H2：** 直接两两 − 逐条打分，在共同的 3 对上。
- **判断：**
  - H1 或 H2 的区间完全在 0 以上 → 写"对这个裁判，比较比打分更准"，并报告在哪些 z 段成立。
  - 区间跨 0 → 写"无可测差别"。
  - 区间完全在 0 以下 → 写"打分更准"，如实报告。

## 事先写下的预测

- z > 2 时三种方式都接近 100%，因为结局（坠毁 vs 着陆）写在摘要里。
- 差别出现在 z < 1：打分的平局率高（分数挤在几个整数上），比较的有效准确率更高。
- 直接两两会有可测的位置偏好，两种顺序的一致性不到 90%。
- 组内排名的两种顺序一致性也不完美，但因为是一次看全组，比直接两两更好。
